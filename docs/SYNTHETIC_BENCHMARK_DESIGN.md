# Synthetic benchmark: a design note

Status: **phase 1 built** (`emerging/validation/synthetic.py`, tests in
`tests/test_synthetic.py`, tracked as P8 in
[RESEARCH_LOG.md](RESEARCH_LOG.md)). First real findings are in
[`findings/synthetic.md`](findings/synthetic.md) — a real, previously-
invisible defect (`nb-trend`'s repeated-look inflation) on the very first
run, which is itself the strongest evidence this was worth building. Scope
is deliberately split: this note covers the aggregate-count generator
(phase 1), which is enough to test every detector discussed in
[LITERATURE_REVIEW.md](LITERATURE_REVIEW.md) sec 1.5 and every EB05 variant
except `--weighted`/`--role-discount`. The case-level generator needed for
those (phase 2) is scoped in §5 but not designed in detail here — not yet
started.

## Motivation

`docs/findings/benchmark.md` scores every detector against
`known_emergences.csv`'s 22 labelled substances, and its own caveats section
names the ceiling on what that can show: **the 95% Wilson CIs on precision
overlap for nearly every model pair in the table.** "Consistently ordered" is
the honest claim the current benchmark supports; "statistically
distinguishable" is not, and more real substances only accrues slowly (LA
County produces a handful of new candidate emergences a year, and most of
those turn out not to be one).

A synthetic set answers a different question than a bigger version of the
same one, and does two things the real data structurally cannot:

1. **Exact ground truth on an axis real data can only infer.** Whether
   Methamphetamine's `nb-trend` alarm was "real but not an emergence" took a
   direct data investigation to establish (`docs/findings/benchmark.md`'s
   Methamphetamine section). For a simulated substance, `emergent` is a
   parameter set at generation time, not a conclusion reached after the
   fact — which means it is also the first place any of these detectors can
   be checked for *calibration* (does a nominal 95% test actually alarm on
   ~5% of true negatives?) rather than only for point-estimate performance.
2. **Monte Carlo replication.** Every profile category can be redrawn
   hundreds of times with fresh noise, which turns "detected 11/22" into an
   actual sampling distribution — recall, precision and lag as measured
   quantities with real confidence intervals, not a single draw's point
   estimate.

**The risk this design has to actively defend against: circularity.**
`nb_trend`'s statistic assumes `log(mu_t) = a + b*t`. A generator whose "in
alarm" cases are *also* log-linear ramps under Poisson noise does not
validate `nb_trend` — it validates that `nb_trend` can recover its own
generative model, which is guaranteed by construction and proves nothing
about real data. Every design choice below is checked against this: does it
give any one detector's own assumptions a free pass? Where the answer is
yes (a pure Poisson, log-linear-ramp scenario), that scenario is kept as a
sanity check, explicitly labelled as such, and never treated as a fair
head-to-head. The **adversarial** scenarios — the ones no detector's own
math already assumes — are the actual point of building this at all, and
several of them are not hypothetical: `docs/findings/benchmark.md` and
`trends.py`'s own docstrings already document real instances (para-
fluorofentanyl's batch arrivals, Methamphetamine's denominator drift,
Morphine/Mirtazapine's reverting blips, Lidocaine's adulterant pattern) that
motivate the specific adversarial cases in §2–§4 rather than a generic
"add some noise" gesture.

## 1. Ground truth: three labels, four simulation parameters

Every synthetic substance is generated from:

| Parameter | Meaning | Drives |
|---|---|---|
| `baseline_rate` | long-run average count/quarter before any rise | emergent vs. non-emergent split (`< EMERGENT_THRESHOLD` vs. `>>`) |
| `rises: bool` | whether there is a true rate change at all | in-alarm vs. not-in-alarm |
| `sustained: bool` | rise holds vs. reverts to baseline (a **blip**) | real rise vs. the Morphine/Mirtazapine negative shape |
| `shape` | functional form of the ramp (§2) | which detector's assumptions get exercised |

Ground truth follows mechanically, no separate labelling step:

| `rises` | `sustained` | `baseline_rate` | Label |
|---|---|---|---|
| False | — | — | **not in alarm** (flat/noise negative) |
| True | False | — | **not in alarm** (blip negative — a real rise, reverted) |
| True | True | `< EMERGENT_THRESHOLD` | **in alarm, emergent** |
| True | True | `>> EMERGENT_THRESHOLD` | **in alarm, non-emergent** (the Fentanyl/PCP/Methamphetamine shape) |

Two more negative shapes are generated by *composition* with §3/§4 rather
than as their own row in this table — see below, since they are not properties
of the substance's own rate at all:

- **denominator-drift negative** — `rises=False`, own rate genuinely flat,
  crossed with a declining `N_t` (§4). Ground truth is still `not in alarm`
  (the count didn't rise); the *share* rises anyway, which is exactly the
  false-positive shape this case exists to manufacture on demand.
- **overdispersed-but-flat negative** — `rises=False`, crossed with clustered
  noise (§3) instead of Poisson. Ground truth is still `not in alarm`; the
  point is to check whether burstiness alone trips a detector with no
  dispersion correction, or an under-corrected one.

**`EMERGENT_THRESHOLD` itself must be a swept parameter, not fixed at the
production value of 2.0.** Reusing 2.0 to *both* generate the ground truth
and read the detector's own `EMERGENT_THRESHOLD`/`nb_trend_emergent` output
would test whether the code can echo back a constant it was handed, not
whether the concept generalizes. Baseline rates near the boundary (0.5x to
4x the threshold) are the informative region and should be oversampled
relative to baselines that are trivially far from it either way.

## 2. Ramp shapes

`shape` picks the functional form of `rate(t)` from onset to the end of the
window (or back to baseline, for a blip). At minimum:

- **step** — `rate` jumps instantly from `baseline_rate` to
  `baseline_rate * magnitude` at `onset`. Favors a period-comparison
  statistic (EB05); tests a slope-based detector's lag, since it has to
  accumulate evidence across several quarters rather than see the whole
  jump in one row.
- **log-linear / exponential** — `log(rate(t)) = log(baseline_rate) + b*(t -
  onset)` for `t >= onset`. `nb_trend`'s own assumed form — kept as the
  sanity-check scenario, never the only one in a reported comparison.
- **sigmoid** — `rate(t)` follows a logistic curve from `baseline_rate` to
  a saturating ceiling. The realistic shape for genuine emergence (fast
  early growth, slowing as the drug captures its addressable share) and
  adversarial for a plain slope test specifically: the back half of a
  sigmoid has near-zero slope while the substance is still newly elevated,
  which is precisely the "detector matches its own assumption" gap a
  log-linear-only benchmark would hide.
- **batch/burst** — not a smooth rate change at all: a small number of
  tightly-clustered arrival times (a Poisson cluster process, or a fixed
  count of deaths spread across 1–2 quarters) superimposed on the baseline.
  Directly modeled on the real precedent `trends.py` already documents for
  para-fluorofentanyl ("arrives in batches rather than at a rate") and the
  single hardest case for `_poisson_trend_slope`'s smooth-curve assumption.
  **Always ground-truth-negative, `sustained` notwithstanding** — a batch
  profile's rate curve concentrates its excess into those 1-2 quarters and
  is flat everywhere else regardless of `sustained`, so it cannot actually
  represent an ongoing rise; `Profile.real_positive` carves this shape out
  rather than letting `sustained=True` claim an elevation the data never
  shows. Found by the profile-gallery figure (`emerging synthetic plot`),
  where a `sustained=True` batch profile and a reverted blip were visually
  indistinguishable but scored with opposite ground truth before the fix.

`magnitude` (fold-increase) and `duration` (quarters to reach the new level,
irrelevant for `step`) are drawn from a range wide enough to include both
easy and marginal cases — a detector that only catches the easy end of the
range is a different result from one that catches nothing, and the current
22-substance set cannot distinguish those (`docs/findings/benchmark.md`'s own
note that Xylazine/Benzylfentanyl-scale detections are the "thinnest" and
most fragile in the whole comparison).

## 3. Noise models

Three regimes, each targeted at a specific correction mechanism rather than
"more realistic noise" in the abstract:

- **Pure Poisson** — `n_t ~ Poisson(rate(t))`. The friendly null: needed to
  check that a nominal-alpha test (`nb_trend`'s Wald z, EB05's EB05>threshold
  reading) actually alarms at close to its nominal rate here, not sufficient
  as the only regime reported.
- **Negative-binomial overdispersion** — `n_t ~ NB(rate(t), phi)` for
  `phi > 1`. Tests whether EB05's pooled, globally-fit `phi`
  (`trends._credit_dispersion`) and `nb_trend`'s locally-fit, per-window
  quasi-likelihood correction (`_poisson_trend_slope`) actually hold their
  false-positive rate under overdispersion, or only appear to on real data
  by chance. `poisson_dispersion`'s own diagnostic
  (`docs/findings/dispersion.md`: 9 of 21 tested substances reject the flat-
  Poisson null) is direct evidence this regime is not a hypothetical for
  this project's real data.
- **Clustered/autocorrelated** — arrivals drawn from a light self-exciting
  process (or a block-bootstrap of the gaps between a real bursty
  substance's own inter-arrival times) rather than independent draws at a
  common rate. The algorithmic version of "batch arrivals" as a *noise*
  property rather than a *shape* property — i.e. this can be layered onto a
  flat, non-rising rate too, which the batch-burst *shape* in §2 cannot (a
  burst shape is definitionally a rise).

## 4. Denominator dynamics — an independent axis

`N_t` (the synthetic county-wide total) gets its own trajectory — flat,
declining (mirroring the real ~18–22% decline `regime()` documents), or
rising — generated independently of any one substance's own rate. Crossing a
flat-own-rate, non-rising substance against a declining `N_t` manufactures
the Methamphetamine-shaped false positive on demand: `share_t = n_t / N_t`
rises even though `n_t` itself never does, with a known-correct label
(`not in alarm`) to score against. This is the direct, purpose-built test of
why Gate B (`eb05_own`) and `nb_trend_own` exist, rather than relying on one
real substance's own history to make the point.

## 5. Scope: aggregate counts (phase 1) vs. case-level records (phase 2)

Everything in §1–§4 only needs `(substance, quarter) -> count` and
`quarter -> N` — exactly `ears_sweep`/`nb_trend_sweep`/`sweep_eb05`'s actual
input shape. That is enough to benchmark every statistic in
`docs/LITERATURE_REVIEW.md` sec 1.5 and every EB05 reading except
`--weighted`/`--role-discount`, whose position-credit machinery
(`causea_order`, `_ever_independent`, `_role_dispersion`) depends on
per-case, cause-line-ordered substance sequences that do not exist at the
aggregate level at all.

**Phase 1 (this design, built first)**: aggregate counts only.

**Phase 2 (scoped, not designed in detail here)**: a synthetic case
generator that emits `(CaseNumber, ordered substance list)` records with a
parametrized adulterant pattern — a fake "trailing substance" that always
rides along with, and only with, a real driver substance, named last on
lines of 3+ — the exact shape `--role-discount` was built to catch
(`GPS_V2_DESIGN.md` §1, the real Lidocaine pattern). Needed before
`--weighted`/`--role-discount` can be benchmarked on synthetic data at all;
revisit once phase 1 is running and validated.

## 6. Integration: extend the existing harness, don't build a parallel one

`validation/benchmark.py` already separates *producing* a sweep from
*scoring* a sweep against ground truth, and `ground_truth.load_ground_truth`
already reads a plain `(substance, interval_start, interval_end,
no_emergence)` CSV. The synthetic module's job is to emit data in those same
two shapes, not a new pipeline:

- **Counts/denominator.** `synthetic.generate(...)` returns `(counts,
  denom)` in exactly `load_quarterly`'s output shape, so `ears_sweep`,
  `nb_trend_sweep` and `sweep_eb05` (which all already take `(counts,
  denom)`, not a mentions path, as their core argument) run unmodified.
- **Ground truth.** A CSV in `known_emergences.csv`'s schema, plus one new
  column real ground truth cannot supply at all: `emergent`. `score_model`
  needs a small, additive extension to score predicted-vs-true `emergent`
  for true positives — a new metric, not a change to any existing one.
- **The one real refactor**: `build_sweeps` currently always calls
  `load_quarterly(mentions, cutoff=cutoff, quiet=quiet)` itself rather than
  accepting a pre-built `(counts, denom)`. It needs an injection point (an
  optional `counts_denom: tuple | None` parameter that skips the
  `load_quarterly` call when given) so `benchmark.run` can point at either
  real mentions or a synthetic draw without two code paths. `--weighted`
  sweeps still call `load_quarterly` internally per as-of quarter
  (`sweep_eb05`, `aberration._sliced_counts`) regardless — phase 1 does not
  touch that, since phase-1 synthetic data has no case-level records for it
  to read in the first place (see §5).

Everything downstream — the `Model` table, the fixed/matched readings, the
Wilson CI, `ensemble-veto-*` — is reusable exactly as built, now run at
Monte Carlo scale (hundreds of replicate substances per profile cell)
instead of one real substance per category.

---

## 7. What this adds beyond the real benchmark, concretely

- **Calibration**, not just performance: for pure-Poisson, non-rising
  replicates, does `nb_trend`'s 1.96 line actually alarm on ~5% of them?
  Does EB05's shrinkage make it more or less conservative than nominal?
  Real data has no true negatives with a known null rate to check this
  against.
- **Power curves**: sweep `baseline_rate` and `magnitude` independently and
  plot detection probability as a function of each, instead of reading
  "Xylazine (n=9) detected, Benzylfentanyl (n=6) missed" as two anecdotes.
- **Per-scenario failure attribution**: because shape/noise/denominator-
  drift are independent, orthogonal axes, a result can say *which specific
  axis* a detector fails on (e.g. "nb-trend is well-calibrated under Poisson
  noise but over-alarms under NB overdispersion at phi > 2") rather than
  "this detector did worse on this substance," which conflates several
  possible causes into one real substance's own idiosyncrasies.

## Prototyping order

1. `emerging/validation/synthetic.py` — profile dataclass (§1), the four
   ramp-shape functions (§2), the three noise samplers (§3), independent
   `N_t` generator (§4). Pure functions, easy to unit-test against known
   closed-form moments (e.g. a Poisson generator's own sample mean/variance
   ratio should be ~1, confirming the sampler before it is ever fed to a
   detector).
2. A `generate_panel(...)` function assembling many replicate substances
   across a parameter grid into one `(counts, denom, ground_truth)` triple,
   with a fixed seed for reproducibility.
3. The `build_sweeps` injection point (§6) — smallest possible diff, checked
   against the existing real-data path with a regression test asserting
   identical output when the injection is unused.
4. Wire `benchmark.run` (or a new `synthetic` CLI command) to accept a
   generated panel and reuse every existing `Model`/`score_model` path.
5. First real run: pure-Poisson sanity check across all models (do the
   already-known easy cases, EB05's own calibration, come back looking
   right?) before trusting any adversarial-scenario result.
6. Adversarial scenarios one axis at a time — overdispersion, then
   denominator drift, then batch arrivals — each checked against the
   specific real finding it is modeled on (Methamphetamine for denominator
   drift, para-fluorofentanyl for batch arrivals) before being read as a
   general result.

## Open questions

- **Replicate count and parameter-grid density** — enough for narrow CIs
  without runtime blowing past the real benchmark's own runtime budget
  (currently a few minutes for the full model table). Start coarse, refine
  once the harness is running and its cost is measured rather than guessed.
- **Seeding discipline** — one fixed global seed for full reproducibility
  vs. a seed per replicate for parallelizability; the existing project
  convention (`_fit_gps_prior`'s deterministic optimizer, TreeScan's own
  Monte Carlo replicate count) favors reproducible-by-default.
- **Where "detectable" magnitude bounds come from** — should the range of
  simulated `magnitude`/`baseline_rate` be anchored to what the real 22
  substances actually span (so results transfer to "would this catch the
  next Xylazine"), or deliberately wider (so the benchmark also charts
  where every detector's power runs out entirely)? Leaning toward both,
  reported separately.
- **Whether to fold `--weighted` calibration into phase 1 at all** via a
  cruder proxy (e.g. inject a fixed *known* discount factor onto some
  fraction of a substance's counts, without simulating real case-level
  co-occurrence) — a shortcut that would not test `--role-discount`'s real
  mechanism (`_ever_independent`, cause-line position) but might still
  usefully stress-test the dispersion correction `_credit_dispersion` was
  built for. Deferred until phase 1 is validated; likely not worth the
  approximation's own risk of a different circularity.
